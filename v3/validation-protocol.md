# V3.3 科学验证规程：从数据更新走向可检验的研究模型

> 状态：**证据门槛和审查流程已实现；尚无独立历史留出集，也未完成参数校准。** 本文禁止将模型内部重复实验误称为现实预测能力。

## 一、当前已知的三种不同证据

| 内容 | 文件与用途 | 可以说什么 | 不能说什么 |
| --- | --- | --- | --- |
| 每日资讯 | 根目录 `hot.json` | 文件按采集管线定期更新，可审计发布时间、抓取时间、来源链接、自标核验状态 | 不证明数据对模型系数进行了重估，也不自动验证每条事实 |
| 镇街资料 | 根目录 `life.json` | 可以检查资料结构、待核查条目和来源链接覆盖 | 人为编辑的热度、商圈描述不是独立可观测的统计因变量 |
| 产业模型 | 根目录 `model.js`（静态源码） | 可以重演给定种子、参数和冲击下的模拟轨迹 | 2025 年内置指标、历史因果链和参数解释不能自动成为 2026 年独立回测结果 |

源码中的 `PARAM_LINEAGE` A/B/C 代表**项目自身宣称的参数血统**。结构常量如 `n_agents`、`ticks` 被标 A 不等于使用官方资料验证过模拟模型。景气指数等模型状态不是 GDP、工业增加值或官方存续率的直接观测。

## 二、校准前置门槛

1. **先冻结研究问题。** 必须明确预测目标、空间尺度、单位、时间频率和预测期限；模型 20 个“时间步”要先给出事前定义的日历映射，不能事后为了吻合统计序列挑时间步。
2. **建立观测口径。** 如果试图验证模型 `abundance`、`order`、`disaster`、`mood`、`survivors`，需要可复现的外部观测映射规则、真实数据的发布页面、计算流程版本和不确定性误差。不能把 GDP 1160 亿元直接塞进范围 [0,1] 的景气指数。
3. **冻结训练/校准期。** 在时间 T 前的历史记录只允许拟合参数；T 后的结果作留出测试。绝不能在校准时观看留出期结果。
4. **检查结构性泄漏。** 当前模型已有编码的历史产业事件和内置指标。任何已写入 `CAUSAL`、`INDICATOR_TABLE` 或默认参数的事件或数值，都不能在未冻结相应模型版本的情况下被称为“独立测试”。
5. **先制定朴素基线。** 对数值尺度上的连续指标，可使用可复现的上一期持平预测等；基线须在看见测试结果前定义并归档。
6. **冻结模型与映射版本。** 保存 Git commit、参数哈希、预测文件及其不可随意修改的归档时间。仅凭 JSON 中填入一个 SHA 不构成第三方时间戳认证。

## 三、历史留出集文件结构

浏览器“科学验证与证据台”采用 `zk-backtest-v1` JSON 结构，要求：

- `schema`: `zk-backtest-v1`
- `scope`: `model-index`；这里**只评分已转换到模型指数范围**的同量纲观测。不支持把现实 GDP 与模型指数直接做 MAE。
- `metric`: `abundance` / `order` / `disaster` / `mood` / `survivors`
- `mapping_id` 与 `mapping_spec_url`: 冻结的、可追溯的现实观测→模型指标规则
- `model_commit`: 对应历史归档预测的 40 位 Git SHA
- `calibration_cutoff`: `YYYY-MM-DD`
- `cases`: 至少 8 条不同 ID 的记录，至少 3 个不同的观测日期。每项包含 `predicted_at`、`observed_at`、`source_url`、`forecast_archive_url`、`predicted`、`observed`、`naive`、`used_in_calibration:false`。日期应满足 `校准截止 < 预测归档 < 观测结果`。

**所有链接必须使用 HTTPS。** 原始数据和档案的内容、数据是否真的独立、预测归档是否不可修改，均需要外部复核：前端程序只能核验结构与自报字段，不能直接认证证据真实性。

## 四、可计算与不能计算的指标

当门槛满足时，浏览器计算：

\[
\mathrm{MAE}=\frac1N\sum_{i=1}^N|\hat y_i-y_i|,\qquad
\mathrm{RMSE}=\sqrt{\frac1N\sum_{i=1}^N(\hat y_i-y_i)^2}.
\]

同口径朴素基线分别计算 MAE、RMSE，并报告模型相对于朴素基线的 MAE 变化比例。基线 MAE 为零时，不计算相对改善比例。

**分数的正式名称为“上传材料的留出集误差”**，而不是“独立验证通过”“模型预测准确率”“仲恺 GDP 预测能力”。

如果缺少独立观测，则显示“不满足回测条件”；不以内部 A/B 多种子结果替代真实历史观察。

## 五、从结构审计到可信度分层

当前 V3.3 已自动完成：

- 仓库 JSON 的日期、数量、来源、核验状态声明检查
- 直接解析 `PARAM_LINEAGE` 并突出需要外部核验的项
- 原始模型源码 SHA-256 指纹展示
- 导入留出数据前的来源、时间顺序、范围、训练泄漏、样本数、日期分布审查
- 合格材料的自报预测 vs 朴素基线误差计算（不做外部认证）

仍未完成：**独立观测清单、时间步映射、历史参数拟合、外部盲测、后续滚动预测验证**。在这些前置条件齐全之前，正式研究报告必须保留“模型演示／现实预测尚未验证”的标识。

## 六、发布与回归测试

任何涉及校准或回测的未来改动都应提交独立 PR，记录模型、数据快照和测试范围。核心模型与豆包 Skills 的采集管线保持原状；V3.3 只新增前端验证审计功能。浏览器自动化需覆盖缺少证据时不评分、错误预测日期不评分、索引尺度不合法不评分、伪数据模板不评分。
